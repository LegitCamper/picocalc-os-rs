# Implementation Plans

## Completed implementation

Plans 001-005 are integrated and host-validated. Plan 006 is a design and isolated
prototype, not a shipped ABI-v2 migration. See [the design](006-abi-v2-design.md)
and the retained `006-abi-v2-prototype.patch`; its application check passes.

`just check` now runs host regressions, C/C++ header checks, formatting, the
kernel build, all five app builds, and loader validation against those rebuilt
ELFs. Additional builds cover both boards with `defmt`, `fps` and `overclock`.
Hardware smoke tests remain unperformed.

Current additions include tracked app allocation cleanup, full buffer-range and
overlap checks, an explicit keyboard output pointer, validated RNG tags, a copied
audio mailbox, exclusive framebuffer ownership, recoverable load/FS errors, and
fallible heap-backed GIF decoding that fits the 16 KiB app stack. Existing launcher
program-deletion changes are preserved.

Important limits: apps still execute privileged native code; pointer validation
is not a sandbox. App panics park instead of busy-spinning but still require a
device reset. A live-allocation count limit is not an app byte quota. Current
18-slot binaries and generated headers must be rebuilt together.

Corrections to the historical audit below:

- The temporary pointer array in `list_dir` lived through its call; it was not a
  dangling pointer. Named storage and explicit returned counts improve clarity.
- A properly used SPSC queue can cross cores. The old unsynchronized mutable
  access was the issue; the replacement channel makes ownership explicit.
- A writer counter cannot repair aliased framebuffer references across DMA.
  The implementation uses a mutex, not the proposed hint-based workaround.
- `set_pixels` had a caller in `clear`; it is removed after replacing that call
  with slice filling. The original "dead code" claim was inaccurate.
- Loader bounds checks do not isolate arbitrary native machine code. MPU and
  privilege separation remain future work.

## Dependency notes

- **001 must land first.** The repo currently has zero tests, no CI, and a
  `CRUSH.md` that documents a Go project. `cargo check --workspace` does not
  work (kernel and apps need different link args). 001 adds `just test` and
  `just check`, which every later plan uses as its verification gate, and makes
  `userlib_sys` host-testable — the only place unit tests can run.
- **002, 003, 004, 005 are independent of each other** and can be executed in
  parallel by different agents. They were deliberately scoped to disjoint
  files to make that safe:
  - 002 → `kernel/src/syscalls.rs` (filesystem + audio syscalls)
  - 003 → `kernel/src/elf.rs`, `kernel/src/ui.rs`
  - 004 → `kernel/src/syscalls.rs` (drawing syscalls only), `kernel/src/framebuffer.rs`, `kernel/src/display.rs`
  - 005 → `userlib/src/lib.rs`, `user_apps/*/src/main.rs`, `kernel/src/main.rs`
  - All four add to the same `mod tests` block in `userlib_sys/src/lib.rs`.
    If run in parallel, expect a trivial merge conflict there; resolve by
    keeping all tests.
- **006 depends on 002, 004 and 005** because its design has to know which
  crashes were already fixed by a return-value convention and which are
  structural. Running it first would produce a design for the wrong problem.

## Considered and rejected

- **`userlib::display::Display::take()`'s `DISPLAY_TAKEN` flag never resets.**
  Not a bug: the flag lives in the app's `.bss`, which the loader re-zeroes on
  every load (`kernel/src/elf.rs:129-132`). Noted in plan 005's "Current state"
  so nobody "fixes" it.
- **`should_full_draw`'s accumulator returns the comparison for clean tiles
  too** (`kernel/src/framebuffer.rs:99-109`). Works correctly; only fragile.
  Mentioned in plan 004's maintenance notes, not worth its own step.
- **`AtomicFrameBuffer::set_pixels` has an inconsistent bounds check**
  (`kernel/src/framebuffer.rs:63-97`). It has no callers — plan 004 deletes it
  rather than fixing it.
- **`TILE_COUNT`/`NUM_TILE_ROWS` use `SCREEN_WIDTH` for both dimensions.**
  Correct today because the screen is square (320×320). Plan 004 adds a
  `const _` assertion instead of a refactor.
- **`kernel/Cargo.toml` declares a `[profile.release]` that cargo ignores**
  (warning on every build: "profiles for the non root package will be
  ignored"). Cosmetic; one line to delete whenever someone is in that file.
- **Replacing `static mut FRAMEBUFFER`/`AUDIO_BUFFER` with a sound ownership
  model.** Right call, wrong time — it is an ABI and lifecycle question, so it
  is folded into plan 006's design rather than attempted piecemeal.
- **MPU-based memory protection for user apps.** The RP2350 has an MPU and
  using it would turn plan 003's bounds checks into defense-in-depth. Too large
  to scope from this audit; recorded as future work in plan 006.

  `kernel/src/heap.rs:37-38` about CAS atomics in PSRAM).
- `kernel/src/usb.rs` and `kernel/src/mtp/` (USB MTP responder), beyond
  confirming they contend for the `SDCARD` mutex.
- `kernel/src/audio.rs`'s PIO program and DMA paths, beyond the buffer
  handshake with `send_audio_buffer`.
- `selection_ui/` and per-app game logic.
- `picolibc/` (git submodule) and the `trouble`/Bluetooth feature (optional,
  currently unused).
- Dependency security (`cargo audit` was not run; the registry cache was cold
  and the audit was read-only/offline).
